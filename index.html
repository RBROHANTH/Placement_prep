Python — common traps to know cold
01
Pythoneasy
List reference vs copy trap — what does this print?
⌄
a = [1, 2, 3] b = a b.append(4) print(a)
Answer: [1, 2, 3, 4] — b = a assigns the reference, not a copy. Both a and b point to the same list. Use b = a.copy() for a separate copy. This is the most common Python trap in placement OAs.
02
Pythonhard
Closure variable capture — what does this print?
⌄
result = [] for i in range(3): result.append(lambda: i) print([f() for f in result])
Answer: [2, 2, 2] — all three lambdas capture the variable i by reference, not its value at creation time. By the time they're called, the loop is done and i = 2. Fix: lambda i=i: i captures value at creation.
03
Pythonmedium
Class variable shared across instances — what prints?
⌄
class Counter: count = 0 def __init__(self): Counter.count += 1 a = Counter() b = Counter() c = Counter() print(Counter.count) print(a.count)
Answer: 3 then 3 — count is a CLASS variable shared across all instances. a.count resolves to the class variable since no instance variable named count exists on a.
04
Pythonmedium
Local vs global scope — what prints?
⌄
x = 10 def change(): x = 20 print(x) change() print(x)
Answer: 20 then 10 — inside change(), x = 20 creates a LOCAL variable. The global x = 10 is untouched. To modify global x, use the global x declaration inside the function.
05
Pythonhard
List concatenation vs mutation in function — what prints?
⌄
def mystery(lst): lst = lst + [99] return lst original = [1, 2, 3] result = mystery(original) print(original) print(result)
Answer: [1, 2, 3] then [1, 2, 3, 99] — lst = lst + [99] creates a NEW list. The original is not mutated. Contrast with lst.append(99) which would mutate the original.
Logical reasoning — types to know
Syllogisms
Read every statement twice. "All A are B" + "Some B are C" does NOT mean "Some A are C". The overlap may not include A. Check if conclusion is DEFINITE, not just possible.
Seating arrangement
Draw it. Don't try to hold it in your head. Fix one person first (usually the one with the most constraints), place others around them.
Number series
Check differences first. If differences aren't constant, check second-order differences. Then check ratios. Then check n(n+1), n², alternating patterns.
Coding-decoding
Check each letter shift first (+1, -1, +2). Then check positional values (A=1, B=2...). Then check reversal or alternating shifts.
Round 2

Group Discussion

20 minutes per batch · 8–12 candidates · Structured communication

Your mock GDs ran unopposed — that's confidence built, not skill built. Real GDs have people cutting in, repeating points, going off-topic, and competing for airtime. Your job is not to fill silence. It's to be the person the room keeps referencing.
Opening formula
Frame + Stand + Invite (first 30 seconds)
"[Topic] has two dimensions most people conflate — [X] and [Y]. I want to address [X] first: [your point in 2 sentences]. I'd like to hear where others stand on this."

Example for "AI replacing jobs":
"AI replacing jobs and AI changing jobs are two different conversations that keep getting merged. The real question isn't whether AI takes tasks — it does — but whether the pace of reskilling can match automation. In India's context, I think it can't without structural intervention. Curious where others stand."

What this does: sets the frame, takes a position, opens the floor — you look like a discussion leader, not a monologuer.
Conclusion formula
Acknowledge both sides + Real tension + Your stand (under 45 seconds)
"We've heard strong arguments on both sides today. The core tension isn't X vs Y — it's [deeper insight]. My position is [clear stand], because [one reason]. That's where I'd leave it."

Don't introduce new points. Don't look at the evaluator — address the group. Then stop. The person who concludes cleanly almost always leaves the strongest impression.
Combat moves — for real GDs
Situation Move
Someone cuts you off "Let me finish this thought —" (calm, firm, no anger). Drop volume slightly, don't shout back.
Someone repeats your point as theirs "Yes, that's what I was building toward — and the extension of that is..." (you own it back without confrontation)
You go blank mid-point "Let me put it this way..." — buys 3 seconds to recover. Never say "umm" and trail off.
Room is chaotic, everyone talking Go quiet for 5 seconds, then speak at normal volume. The contrast cuts through noise better than shouting.
Someone makes a weak argument "That's one way to look at it — the counterpoint would be..." Never attack the person, attack the argument.
You want airtime but can't get in Make eye contact with the most agreeable person, nod, then speak. Social permission granted.
You've made your points, room is still going Shift to synthesis mode: "So far we've established X and Y — the gap we haven't addressed is Z." You're elevating, not repeating.
Quiet person acknowledgement "[Name], you looked like you had something to add on this." High-risk, high-reward. Do it once max.

10 questions they will definitely ask
01

02
OOPeasy
What is the difference between an abstract class and an interface?
⌄
Abstract class: can have concrete + abstract methods, can have state (fields), single inheritance only. Interface: only method contracts, no state, multiple interfaces per class. Use abstract class for "is-a" with shared code (Animal with name field + abstract sound()). Use interface for "can-do" (Serializable — Dog and File both implement it). In your projects: Unity's MonoBehaviour is effectively an abstract class you extend. Custom enemy behaviours are a candidate for interface design.
03
DBMSeasy
Explain ACID properties with a real example.
⌄
Use bank transfer: Atomicity — debit A and credit B must both succeed or both fail. Consistency — total money before = total money after. Isolation — two simultaneous withdrawals from same account don't interfere. Durability — after commit confirmation, the transfer survives even if the server crashes. These are the foundation of why ERP systems like ERPNext can be trusted with financial data.
04
DBMSmedium
Explain normalization — 1NF, 2NF, 3NF with examples.
⌄
1NF: atomic values — no arrays. Violation: storing "9876,8765" in PhoneNumber. Fix: one row per phone. 2NF: no partial dependency on composite key. Violation: (StudentID, CourseID) PK but CourseName depends only on CourseID. Fix: separate Course table. 3NF: no transitive dependency. Violation: StudentID → ZipCode → City. Fix: separate Zip table. Each NF removes a specific type of anomaly: insertion, update, or deletion anomaly.
05
Pythonmedium
What are Python decorators? Give a practical example.
⌄
A decorator wraps a function to add behaviour without modifying it. Syntax: @decorator_name. Example: @timer measures execution time. Real uses: @login_required in web frameworks, @staticmethod, @classmethod, @property, @lru_cache for memoization. Frappe framework uses decorators extensively for route definitions and permission checks — so this is directly relevant to Tridots' stack.
06
OOPmedium
Explain the SOLID principles with one example each.
⌄
S — Single Responsibility: AmbuliSoundManager only handles sound events, not enemy movement. O — Open/Closed: Enemy base class open for extension (new enemy types) closed for modification. L — Liskov Substitution: any subclass of Enemy works wherever Enemy is expected. I — Interface Segregation: don't force a class to implement methods it doesn't need — split large interfaces. D — Dependency Inversion: game logic depends on IEnemy interface, not AmbuliEnemy concretely — easier to test and swap.
07
DBMSmedium
What is indexing? Clustered vs non-clustered?
⌄
Index is a data structure (B-Tree) that speeds up retrieval — like a book index. Without index: O(n) full scan. With index: O(log n). Clustered: physically reorders table rows — only one per table, usually PK. Data IS the index. Non-clustered: separate structure with row pointers — multiple allowed. Trade-off: faster reads, slower writes (index updated on every INSERT/UPDATE/DELETE). In ERPNext with MariaDB, PK indexes are always clustered.
08
Projectshard
If you were to scale your Bug Reporting Portal to 10,000 users, what would change?
⌄
Current: single Express server, single MongoDB. At scale: (1) Horizontal scaling — multiple Node instances behind Nginx load balancer. (2) MongoDB replica sets for read scaling. (3) Redis for caching frequent bug lists. (4) S3 or object storage for file attachments. (5) Message queue (Bull/RabbitMQ) for async notification processing. (6) JWT-based stateless auth middleware. Core principle: decouple stateful from stateless, separate read path from write path.
09
Pythonhard
What is Python's GIL and why does it matter?
⌄
GIL (Global Interpreter Lock) allows only one thread to execute Python bytecode at a time — even on multi-core processors. Problem: threads can't achieve true parallelism for CPU-bound tasks. Why it exists: simplifies CPython's reference counting garbage collector. Workaround: multiprocessing module (separate processes, each with own GIL) for CPU-bound work. GIL doesn't hurt I/O-bound tasks much — threads release GIL during I/O waits, so web servers handle many requests fine.
10
DBMShard
What is BCNF and how is it different from 3NF?
⌄
3NF: for every FD X→Y, either X is a superkey OR Y is part of a candidate key. BCNF: X MUST be a superkey — no exception. BCNF is stricter. Example: Table(StudentID, Course, Teacher). FDs: (StudentID,Course)→Teacher and Teacher→Course. In 3NF because Teacher→Course: Course is part of candidate key. BCNF fails because Teacher is not a superkey. Fix: decompose into Teacher(Teacher,Course) and Enrollment(StudentID,Teacher). BCNF may not preserve all FDs — that's the trade-off.
